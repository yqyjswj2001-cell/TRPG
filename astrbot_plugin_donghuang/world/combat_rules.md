# 回合制战斗系统规范（新写，非原总纲内容）

> 本文件是新写的规则模块，实现"修仙世界战斗系统"，跟 `engine_rules.md`
> 第16/18节的"回合制战斗"修订口子对齐。**这是给开发者/维护者看的规则
> 说明书，不是运行时会被读进 AI prompt 的文件**——`main.py` 里的
> `_resolve_combat_round`/`_combat_player_action` 每回合只把代码已经
> 算好的"事实行动列表"（谁命中了、扣了多少血）拼成一段纯文本喂给 AI，
> AI 从来不会读到这份文件本身的内容。之前这里写过"只在 /dh combat
> 期间才加载"，实际代码里从未有过这个加载动作——已修正为准确描述，
> 避免文档承诺了代码没做的事。
>
> **核心原则（贯穿全文）**：先攻/命中/伤害/状态效果的施加与消退，全部由
> 插件代码摇骰/查表决定；AI 只负责把代码已经算好的结果写成一段连贯的
> 战斗叙事，绝不允许自己编造伤害数字、状态效果或战斗结果。这是"代码管
> 数字、AI 管叙事"原则在战斗场景下的具体落地——本地小模型逐回合亲自
> 计算血量/命中很容易出错，交给代码摇骰能保证每一场战斗都公平、可复现。

## 步骤 1：核心参数与状态效果

### 核心参数

| 参数 | 说明 | 存储位置 |
| --- | --- | --- |
| 气血（HP） | 已有字段，归零进入濒死，走 `death_protocol.md` 流程 | `profile.hp{current,max}` |
| 灵力（MP） | 施法消耗的资源，角色开局固定 15/15，目前不随境界/属性成长（MVP 简化） | `profile.mp{current,max}` |
| 攻击力 | 临时计算值，不存档：`(根骨-10)//2 + 境界序数//2 + 3`，武器/法宝按品阶加成 | `_combat_stats()` 现算 |
| 防御力 | 临时计算值：`(体质-10)//2 + 境界序数//2 + 8` | `_combat_stats()` 现算 |
| 先攻修正 | 临时计算值：`(根骨-10)//2` | `_combat_stats()` 现算 |
| 境界等级 | 已有 `cultivation_realm`，境界序数取自 `_REALMS` 列表下标，只影响攻防数值，不直接决定胜负 | `profile.cultivation_realm` |

攻击力/防御力/先攻修正**不写进存档**，每次结算时从六维属性+境界+装备
现算，避免出现"档案里的战斗数值"和"角色实际状态"不同步的问题。

### 状态效果池（`STATUS_EFFECTS`，代码定死，不可扩展）

| 状态 | 机制 | 持续回合 |
| --- | --- | --- |
| 眩晕 | 本回合无法行动 | 1 |
| 中毒 | 每回合损失3点气血 | 3 |
| 灼烧 | 每回合损失6点气血，比中毒更痛但消退更快 | 2 |
| 破甲 | 防御力 -3 | 2 |
| 护盾 | 吸收下一次命中的10点伤害（命中一次即消耗，不看剩余回合数） | 2 |
| 加速 | 攻击力 +3 | 2 |
| 灵气紊乱 | 施法灵力消耗 ×1.5 | 2 |

AI 不能在叙事里发明这张表以外的状态效果；代码在解析 AI 的战斗叙事时也
**不会**从自由文本里反向解析出新状态——状态效果只能由代码在结算逻辑里
主动施加（比如"防御"动作施加护盾，命中判定判定为大失败时可能附带
"破甲"，具体见步骤2）。

## 步骤 2：回合流程

### 发起

团长发送 `/dh combat [妖兽名字] [黄级/玄级/地级/天级]`（两个参数都可省略）。
代码：
1. 按品阶随机生成一只妖兽的战斗数值（`_generate_monster`），名字来自
   代码小样本池或团长指定，不需要额外调用 AI。
2. 给所有在场存活玩家 + 妖兽摇一次先攻（`1d20 + 先攻修正`），混合排序
   得到 `initiative_order`。
3. 复用现有"回合锁定"机制收集玩家本回合的行动文本（`turn_lock`），
   不是每个阶段单独收集——**一句话描述本回合要做什么**即可。

### 单回合结算伪代码

```
function resolve_round(combat):
    for actor in combat.initiative_order:
        if actor not in combat.remaining_slots and actor != monster_id:
            continue  # 已阵亡/已逃跑，跳过

        if actor is 妖兽:
            if 妖兽.hp <= 0: continue
            apply_status_tick(妖兽)              # 中毒/灼烧扣血，持续回合-1
            if 妖兽被眩晕: 记录"无法行动"; continue
            target = 存活玩家中气血最低者
            hit, dmg = roll_attack(妖兽.atk, target.def + 状态修正)
            if hit:
                dmg = consume_shield(target, dmg)
                target.hp -= dmg
                if target.hp <= 0: target.生存状态 = "dying"
            记录这次攻击的事实文本
            continue

        player = actor
        if player.生存状态 != "stable": continue  # 濒死/死亡角色本回合不能行动
        apply_status_tick(player)
        if player被眩晕: 记录"无法行动"; continue

        action = classify(player提交的自然语言文本)  # 关键词匹配，不调用AI
        switch action:
            case 逃跑:
                roll = 1d20 + 根骨修正
                if roll >= 妖兽品阶对应DC: 移出战斗，记录"逃跑成功"
                else: 记录"逃跑失败，浪费本回合"
            case 防御:
                施加"护盾"状态
                记录"摆出防御姿态"
            case 施法（文本包含已知功法名）:
                cost = 5 * 灵气紊乱倍率
                if player.mp < cost: 记录"灵力不足，施法落空"
                else:
                    player.mp -= cost
                    hit, dmg = roll_attack(player.atk + 3, 妖兽.def)
                    if hit: dmg = consume_shield(妖兽, dmg); 妖兽.hp -= dmg
                    记录这次施法的事实文本
            case 使用物品（文本包含持有物品名）:
                找到并移除该物品；按品阶查表恢复气血
                记录"使用XX，恢复N点气血"
            default（普通攻击）:
                hit, dmg = roll_attack(player.atk, 妖兽.def)
                if hit: dmg = consume_shield(妖兽, dmg); 妖兽.hp -= dmg
                记录这次攻击的事实文本

    combat.remaining_slots -= 本回合逃跑的玩家
    if 妖兽.hp <= 0: 战斗胜利，结束
    elif 没有存活玩家留在战斗里: 战斗落败/全员撤退，结束
    else: 回合数+1，重新打开 turn_lock 等下一回合的行动
```

真正的实现见 `main.py` 里的 `_resolve_combat_round`/`_combat_player_action`，
跟上面的伪代码逐步对应，不是另一套逻辑。

### 阶段划分说明（相对简化）

原始需求里的"先攻判定→行动阶段（移动/物品/施法/攻击）→反应阶段→结束
阶段"在本插件里做了合并简化：**没有独立的"移动"阶段**（区域内战斗默认
双方都在同一交战范围，不做网格/距离模拟）；**没有独立的"反应阶段"**（
闪避/格挡已经内含在命中判定的防御力里，不需要玩家额外声明一次"反应"）；
"行动阶段"和"结束阶段"合并成上面伪代码里的单回合循环——防御/护盾这类
"反应型"效果通过玩家主动选择"防御"动作来触发，不是被动询问。这是刻意
的简化，符合"轻量，不追求过度硬核机械感"的整体调性。

## 步骤 3：修仙特有元素

- **灵力池与法术**：施法从 `profile.mp.current` 扣灵力，固定消耗5点
  （受"灵气紊乱"状态×1.5影响），灵力不足则施法直接落空（不进入伤害
  判定）。法术伤害在普通攻击基础上 +3 攻击力加成，具体命中判定跟普通
  攻击共用 `roll_attack`。
- **法宝/武器使用**：不需要战斗中额外"装备"动作——角色开局或后续获得
  的法宝/武器已经通过 `RESOURCE_STATE.held` 里的品阶自动折算成攻击力
  加成（黄+2/玄+5/地+12/天+25），战斗全程生效，不需要每回合重新声明。
- **丹药的即时效果**：战斗中提到已持有的丹药/灵材名字，视为"使用物品"
  动作，代码核实持有后移除，按品阶恢复气血（黄+15/玄+35/地+70/天+150），
  是即时效果，不做"持续回合恢复"（避免额外增加要追踪的状态字段）。
- **阵法**：MVP 阶段**不做**独立的"布阵/破阵"子系统（这需要额外的空间/
  节点建模，超出当前"轻量"定位）。如果情节需要阵法效果，团长可以在
  `/dh combat` 发起前，通过既有的 STATE_DELTA 机制给某一方临时施加一个
  `combat_status` 里已有的状态（比如战场遍布毒雾，提前给妖兽或某位玩家
  加一个"中毒"状态）。这是一个明确记录的功能缺口，不是遗漏。

## 步骤 4：AI 接口规范

跟六类正式事件的"STATE_DELTA/标签代码块"惯例保持一致，**不采用**逐回合
双向 JSON 协议——本地模型逐回合稳定输出严格 JSON 的可靠性不如"code 直接
产出事实文本，AI 只读不改"。具体接口：

**输入（代码 → AI，每回合一次调用）**：一段纯文本 prompt，包含：
- 当前回合数、对手名字
- 本回合已经结算好的"事实行动列表"（每个参与者一行，格式：
  `{名字}：{发生了什么}（{关键数字}）`）
- 如果战斗结束，附加一句"战斗结果"提示（胜利/全灭撤退）
- 如果战斗胜利，附加战利品参考道具提示（复用 `_build_event_item_hint`）
- 明确要求："不要编造上面没有提到的伤害数字或状态效果"

示例内部数据结构（`campaign["combat"]`，实际是 Python dict，落盘时序列化
成 JSON，不是给 AI 读的协议，只是内部状态）：
```json
{
  "active": true,
  "round": 2,
  "initiative_order": ["PLAYER-A", "M1", "PLAYER-B"],
  "remaining_slots": ["PLAYER-A", "PLAYER-B"],
  "monsters": {
    "M1": {
      "name": "赤鳞妖虎", "tier": "黄级",
      "hp": 28, "hp_max": 45, "mp": 12, "mp_max": 15,
      "atk": 5, "def": 4, "initiative_mod": 2,
      "status": [{"name": "破甲", "turns_left": 1}]
    }
  }
}
```

**行动指令格式（玩家 → 代码）**：不要求玩家发送 JSON，就是普通中文
一句话（"我用火球术轰它""我防御""我逃跑""我吃了那颗回气丹"），代码用
关键词+"是否包含已知功法/持有物品名字"来分类，分类逻辑见步骤2伪代码里
的 `classify()`。这是刻意的降级——比起要求玩家和本地模型都精确遵守
严格 JSON 格式，关键词匹配对参与者更友好，出错时的后果也更可控（顶多
被归类成"普通攻击"，不会整回合解析失败）。

**输出（代码 → 群聊）**：AI 返回的战斗叙事文本，前面带 `⚔️ 第N回合`/
`⚔️ 战斗结束` 前缀，附上对手当前气血。所有 HP/MP/状态变化已经落盘到
`player_profiles.json`，群里看到的是叙事结果，不是原始数值（想查看自己
剩余气血/灵力可以用已有的 `/dh mycard`）。

## 步骤 5：完整战斗示例

设定：李昂（练气三层，六维中根骨14）和张衡（练气二层，六维中体质15）
遭遇一只黄级"赤鳞妖虎"（HP 42、攻5、防3）。

**发起**：
```
团长: /dh combat 赤鳞妖虎 黄级
机器人: ⚔️ 战斗开始！对手：赤鳞妖虎（黄级，气血42）
        先攻顺序：李昂、赤鳞妖虎、张衡
        请在场玩家用一句话描述本回合行动（攻击/防御/施法「功法名」/使用
        「物品名」/逃跑），团长可以 /dh force 跳过没交行动的人。
```

**第1回合**（代码内部结算，示意）：
- 李昂（先攻）：提交"我挥剑砍向妖虎" → 默认攻击 → `roll_attack(李昂.atk=5, 妖虎.def=3)` →
  命中，伤害7 → 妖虎 HP 42→35
- 赤鳞妖虎：攻击气血较低者（此时张衡未提交，视为待定，先跳过妖虎回合直到双方交齐）
- 张衡：提交"我用回气诀恢复状态，先观察" → 不含攻击/防御/逃跑/物品关键词 → 归为默认攻击 →
  `roll_attack(张衡.atk=4, 妖虎.def=3)` → 未命中

AI 收到的 prompt 大致是：
```
第1回合，战斗对手：赤鳞妖虎。以下是这个回合已经由代码算好的真实结果，
请把它们写成一段紧凑、有画面感的战斗叙事：
李昂：出手攻击赤鳞妖虎，命中造成7点伤害（妖兽剩余气血35/42）
赤鳞妖虎 攻击 张衡：命中造成4点伤害（剩余气血26/30）
张衡：出手攻击赤鳞妖虎，但没有命中
请不要编造上面没有提到的伤害数字或状态效果。
```

群里看到的输出：
```
机器人: ⚔️ 第2回合
        🎭 李昂一剑劈开虎首侧翼，赤鳞妖虎低吼着甩尾扫向张衡——张衡堪堪
        侧身，肩头还是被虎爪擦破了几分皮肉。张衡咬牙挥掌反击，却被妖虎
        灵活避开。
        （对手气血 35/42，请继续描述行动）
```

**后续回合**持续到妖虎气血归零（战斗胜利，写入团史，参与者获得一次性
战斗历练加成）或李昂/张衡双双濒死/逃离（战斗落败/撤退收尾，濒死角色
按 `death_protocol.md` 走后续的死亡豁免/团长确认流程）。

## MVP 范围说明

跟插件其它模块一样，这版战斗系统**没有实现**：多个妖兽同时参战（目前
固定单体 `M1`）、阵法子系统、法术种类差异化（所有已知功法机制上等同，
只是叙事标签不同）、灵力随境界/属性成长。这些都是明确记录的功能缺口，
不是遗漏，后续如果需要可以在这份规范基础上扩展，不需要推倒重来。
