# 使用说明 —— 东荒修仙 TRPG

> 这份文档写给**在群里实际玩这个团的人**看（团长、玩家），不涉及安装和
> 代码。安装、依赖、数据结构这些技术信息请看同目录下的 `README.md`。

## 这个插件能干什么

这是专门为"东荒"这个硬核修仙世界观做的跑团机器人。装上之后，AI 会自动
当团长：开团时现场生成一个有血有肉的世界、给每个人随机生成一个角色、
判断你说的话是普通互动还是触发了重大事件、给出剧情反馈、管理世界的状态
（谁在哪、势力怎么样、发生过什么事），还有一套完整的死亡与重生规则。

这不是个空壳世界——五大区域各有正式名字和具体的子区域/地点、17个有名
有姓的具体势力、几百个具名 NPC、十万条功法和几十万件法宝武器丹药灵材，
角色也会随着真实的游戏行动（打坐修炼、正式事件、服用物品等）真正变强，
不是境界文字换一下就完事，还有一套会翻旧账的因果网络，和区域/势力之间
真实存在的资源流动。

每个角色还会被悄悄埋一条**只有机器人知道、玩家自己不知道**的隐藏主线，
需要在游戏过程里自己摸索发现，这条线最终会牵连到一个尚未显现的世界级
大事件——目的是让每个人都真正"活"在这个世界里，体会人情世故、善恶抉择，
一步步走出自己的路，而不是走个流程掷骰子。

所有指令前面的 `/` 是机器人默认的唤醒前缀，如果你们改过前缀，就把下面
例子里的 `/` 换成你们自己的前缀。

## 示例一：报名

`/dh join` 现在只是报名，**不会**现场问你任何建卡问题——你的角色会在
团长 `/dh start` 正式开团的那一刻，完全随机生成：

```
玩家A: /dh join
机器人: ✅ 报名成功！你现在不用做任何事，等团长 /dh start 正式开团时，
        你的角色会完全随机生成，一次性正式登场。

玩家B: /dh join
玩家C: /dh join
（至少3人报名后，团长才能开团）
```

## 一个人怎么测试

正式开团至少需要 3 人报名，如果你只是想自己一个人先测测机器人能不能
正常跑起来，管理员可以用 `/dh testfill` 把剩下的名额一键填成"测试占位
玩家"，这样自己一个人也能 `/dh start`：

```
你: /dh join

你（管理员）: /dh testfill
机器人: 🧪 已用 2 个测试占位玩家填满剩余名额。
        现在可以 /dh start 了——测试占位玩家跟真人一样会在开团时生成一个
        完全随机的角色，只是不会真的发消息，如果之后触发了回合锁定一直
        等不到它们交行动，用 /dh force 跳过等待即可。

你: /dh start
```

## 示例二：正式开团 —— 先讲世界，再一个个介绍角色

至少 3 人报名后，团长发 `/dh start`。机器人会依次做三件事：

**第一步：先给全团讲一段简短的世界观介绍**（不是甩一堆术语，是一段通俗、
有画面感的开场白）：

```
团长: /dh start
机器人: 🌄 东荒，一个灵气渐衰、人心浮动的修仙世界。中部的老牌宗门守着
        日渐枯竭的祖脉苦苦支撑，东边新崛起的势力却在悄悄招兵买马；南方
        的村镇为了赈灾天天愁眉不展，西境的废墟里流传着不知真假的鬼神
        传说……这是一个资源有限、人心复杂的时代，你的每一个选择都会
        留下痕迹。
```

**第二步和第三步是"两步走"，不会一次性把所有内容甩给你**：

**第二步：先给每个人 @ 发一份【角色面板】**，包括姓名、年龄（15-25岁）、
性别、身高、修为、身份、灵根属性、灵根级别、六维属性、天赋/特质：

```
机器人: @李昂的QQ号
        【角色面板】
        姓名：李昂　年龄：19　性别：男　身高：176cm
        修为：练气三层　身份：中部铁匠铺打杂三年的学徒
        灵根属性：火　灵根级别：玄阶
        六维：根骨14　悟性11　机缘9　魅力13　体质15　心性10
        天赋/特质：资质平平，没有过人之处
        请确认角色面板，确认后我将为你生成专属的因果事件。
（紧接着另发一条给下一位玩家）
```

**第三步：等你随便回一句话确认（回什么都行，不用非得回"确认"两个字），
机器人才会单独给你生成一段专属的开局因果事件**——纯故事叙事，不带任何
标题、标签或选项，读起来像小说开头，不是数据面板：

```
玩家A: 确认
机器人: 铁匠铺后院的炉火忽明忽暗，李昂蹲下身去添炭，指尖忽然触到一块滚烫
        的赤色矿石——三天前雷雨夜从天而降，砸穿了柴房的顶棚。他把它揣进
        怀里那一刻，炉火猛地窜高一截，映得满墙通红。
```

**注意几个关键点**：
- **开局位置完全随机，不强制分开**——运气好大家可能凑在同一个地方，运气
  不好也可能天各一方，机器人不会刻意把玩家拆开。
- **身份和天赋是按稀有度抽的**，大多数人就是普通杂役、外门弟子，资质平平；
  "内门天才""绝世妖孽"这种是极小概率，别指望人人都是天选之子。
- 每次开局因果事件用的"因"（异象/征兆）**同一个团里不会重复**，天降血雨、
  古钟自鸣、灵泉干涸……每个人遇到的都不一样。
- 你看到的这些信息里**没有"主线任务"或者"隐藏剧情"**——因为真的有一条，
  但故意不告诉你。要靠你自己在后面的剧情里一点点碰出来。**别想着靠问
  机器人套出来，它不会说。**
- 六维属性（根骨/悟性/机缘/魅力/体质/心性）是真随机生成的（不是 AI 编的
  假随机），保证公平。

## 示例三：普通互动，AI 立刻给反馈

开团之后，正常发言描述你的角色在做什么，AI 会自动判断这是不是需要回应，
是的话立刻给一段简短的剧情反馈（不会写一大段小说，通常就一两句话，也
不会堆一堆"因果""结构偏移"这种生硬的术语）：

```
玩家A: 我把怀里那块烫手的矿石拿出来，找镇上的老匠人问问是什么来头
机器人: 🎭 老匠人接过矿石，手指刚碰到就猛地缩回，脸色一下子变了：
        "这东西……你从哪儿捡的？快收起来，别让人看见。"
```

如果你只是在群里闲聊、吐槽（跟角色行动无关），AI 会判断出来，不会打扰你。

## 示例四：触发重大事件，等大家一起交行动

有六类"正式事件"（势力冲突、灵脉资源、修行突破、因果回响、CHAOS异常、
遗迹与机缘），一旦你的发言触发了这种事件，机器人不会立刻给你一个人结算，
而是等所有在场玩家都交上自己的行动，再一次性统一结算：

```
玩家A: 我决定直接把矿石交给宗门长老，问个明白
机器人: ⚠️ 触发正式事件：因果回响！
        等待以下玩家提交行动：沈砚、王曦
        （团长可以用 /dh force 跳过等待，直接结算）

玩家B（沈砚）: 我按信上的地址去赴约，看看对方到底想干什么
玩家C（王曦）: 我留在原地，观察最近镇上的异常动静
机器人: ✅ 已收到 王曦 的行动，等待其余玩家提交……
（都交齐后自动统一结算）
机器人: 🎭 长老盯着那块矿石看了许久，缓缓开口："这不是凡物，你带来的，
        恐怕不只是麻烦……"
```

如果有人迟迟不交行动，团长可以发 `/dh force` 强制结算，需要发两次才真正执行：

```
团长: /dh force
机器人: ⚠️ 即将强制结算「因果回响」事件：
        已交行动：王曦
        还未交：沈砚
        未交行动的玩家这次事件里将视为没有主动行动。确认结算请再次发送 /dh force。

团长: /dh force
机器人: 🎭 长老盯着那块矿石看了许久，缓缓开口："这不是凡物，你带来的，
        恐怕不只是麻烦……"
```

第一次发送只是列出目前的交行动情况，方便团长确认没有等错人；确认无误后再发一次才会
真正结算。注意：第二次发送会直接执行，不会再重新核对一遍名单，所以如果在两次发送之间
又有人补交了行动，想看最新情况就先别急着发第二次。

## 示例五：死亡与重生的完整流程

```
（某次事件结算后，李昂的 HP 归零，进入"濒死"状态）

李昂: /dh save
机器人: 🎲 李昂 死亡豁免失败（1/3），仍处于濒死状态。

沈砚: /dh stabilize 李昂的QQ号
机器人: ❌ 稳定检定失败，李昂 仍处于濒死状态。

李昂: /dh save
机器人: 🎲 李昂 死亡豁免失败（2/3），仍处于濒死状态。

李昂: /dh save
机器人: 💀 李昂 死亡豁免连续失败 3 次，达到死亡判定条件！
        ⚠️ 死亡判定尚未生效，需要 AstrBot 管理员用 /dh confirmdeath 李昂 确认，
        或 /dh rejectdeath 李昂 否决。

团长: /dh confirmdeath 李昂
机器人: 💀 李昂 死亡判定已确认，写入事件记录 E000004。
        角色不会继承任何属性/装备到新角色。请该玩家发送 /dh join 重新报名
        （下次开团时会拿到一个全新的随机角色）。
```

**注意**：
- `/dh confirmdeath`/`/dh rejectdeath` 后面填的是**角色名**，不是内部代号。
- 死亡判定必须由团长/管理员确认或否决才会生效，AI 自己不会擅自判定
  死亡——哪怕死亡豁免已经连续失败 3 次，也只是进入"等待确认"状态。

## 示例六：暂停与结束游戏

```
团长（想暂时休息）: /dh stop
机器人: ⏸️ 游戏已暂停，所有存档已保留。
        随时可以 /dh start 继续游戏。

（大家吃完饭回来）

团长: /dh start
机器人: 🌄 东荒的故事仍在继续……
（世界状态、角色档案全部完好无损）

（游戏打通了，要彻底结束）

团长: /dh end
机器人: ⚠️ 确认结束游戏并清空本群所有存档吗？
        包括：角色档案、世界状态、事件历史、报名信息。
        此操作不可恢复！如果确认，请再次发送 /dh end。

团长: /dh end
机器人: 🔚 本团已结束，本群所有存档已清空。想重新开始请 /dh join 报名。
```

**注意**：
- `/dh stop` 只是暂停，**不会删任何东西**，随时 `/dh start` 就能继续。
- `/dh end` 会**永久清空**本群所有存档，而且**发一次不算，必须连发两次**
  才执行——防止手滑。

## 示例七：道具、团史、世界局势、中途加入/退出

```
李昂: /dh items
机器人: 【李昂 持有的资源】
        灵石：15
        随身携带：一把生锈的短刀

（想把东西给队友不用专门指令，直接跟AI描述这个意图）
李昂: 我把这把生锈的短刀给了张衡
机器人: 🎭 李昂把那把用惯了的短刀塞到张衡手里："这个你拿着，我这两天用不上。"

李昂: /dh items
机器人: 【李昂 持有的资源】
        灵石：15
        （随身没有其它物品）

任意玩家: /dh world
机器人: 🗺️ 东荒当前局势
        大势：动荡　灵气流向：中部向东部迁移　CHAOS活跃度：活跃-非世界级
        【区域态势】
        · 中部：……

任意玩家: /dh history
机器人: 📜 东荒团史（最近5条，共8条）
        [E000001] 灵脉资源｜李昂、张衡
        　东荒开局
        ……

（中途有新朋友想加入，团已经在进行中）
新玩家: /dh join
机器人: ✅ 中途报名成功，正在为你单独生成角色……
        （随后单独收到自己的角色面板，跟正常开局一样先确认再触发因果事件）

（有人临时要离开，不想继续玩了）
玩家: /dh logout
机器人: 👋 李昂 已退出游戏，不再参与后续剧情判定。空出的槽位可以被新玩家 /dh join 顶替。
```

**注意**：
- 转手物品/花灵石不设专门指令——直接在群里口头描述，AI 会判断这次转手/花费
  合不合理；代码只负责核实"东西是不是真的在你身上""灵石数额有没有超出单次
  波动上限"，不会凭空移动一件角色实际上没有的东西。
- `/dh logout` 不会删掉角色档案，只是不再参与剧情判定和回合锁定等待；想再玩要重新
  `/dh join`，会顶替一个空槽位、重新生成角色，不继承旧角色任何东西。
- 中途 `/dh join` 只会为这一个新角色单独生成区域和角色面板，不会打断正在进行的剧情。

## 示例八：团务管理（名单/踢人/拉黑/导出）

```
团长: /dh roster
机器人: 👥 本团名单（active）
        1. [PLAYER-A] QQ:123456　李昂　状态:claimed
        2. [PLAYER-B] QQ:654321　张衡　状态:claimed
        3. [PLAYER-C] 空位
        ……

（有玩家一直不说话，团长决定把TA踢出去）
团长: /dh kick 李昂
机器人: ✅ 已把 李昂 踢出游戏，不再参与后续剧情判定。空出的槽位可以被新玩家 /dh join 顶替。

（有个捣乱的QQ号不想让TA再进来）
团长: /dh blacklist 999999
机器人: 🚫 已拉黑 QQ 999999，TA 无法再 /dh join 本团

（团结束前想留个记录）
团长: /dh export
机器人: ✅ 已导出团务记录到：
        .../plugin_data/astrbot_plugin_donghuang/logs/群号/export_20260705_201500.txt
```

**注意**：
- `/dh kick` 开团前用等于帮玩家取消报名；开团后用等于强制执行一次 `/dh logout`。
- `/dh blacklist` 只挡 `/dh join`，不会把已经在团里的角色弄出去，两者要配合用。
- `/dh export` 导出的是**完整**团史（不像 `/dh history` 只看最近几条），文件存在本地磁盘上，
  不会在群里以任何形式展示 QQ 号以外的隐私信息。
- 这几个指令都要求 AstrBot 管理员权限，普通玩家用了会被拒绝。

## 示例九：回合制战斗

```
团长: /dh combat 赤鳞妖虎 黄级
机器人: ⚔️ 战斗开始！对手：赤鳞妖虎（黄级，气血42）
        先攻顺序：李昂、赤鳞妖虎、张衡
        请在场玩家用一句话描述本回合行动（攻击/防御/施法「功法名」/使用
        「物品名」/逃跑），团长可以 /dh force 跳过没交行动的人。

李昂: 我挥剑砍向妖虎
张衡: 我用回气诀恢复状态，先观察一下

机器人: ⚔️ 第2回合
        🎭 李昂一剑劈开虎首侧翼，赤鳞妖虎低吼着甩尾扫向张衡——张衡堪堪
        侧身，肩头还是被虎爪擦破了几分皮肉。张衡咬牙挥掌反击，却被妖虎
        灵活避开。
        （对手气血 35/42，请继续描述行动）

……（战斗持续到妖虎气血归零，或角色濒死/逃离）

机器人: ⚔️ 战斗结束（第4回合）
        🎭 李昂一剑贯穿虎颈，赤鳞妖虎轰然倒地，再无声息。
```

**注意**：
- 先攻顺序、命中、伤害、状态效果全部由代码摇骰算好，AI 只负责把结果写成
  战斗叙事，不会自己编造伤害数字——想看自己当前气血/灵力，随时 `/dh mycard`。
- 行动不用套固定格式，正常说话就行：提到"逃""防御"这类词会被识别成对应
  动作；提到自己已学会的功法名字会被识别成施法；提到自己持有的物品名字
  会被识别成使用物品（一般是丹药回血）；其余一律按普通攻击处理。
- 战斗中有人濒死，走的是已有的死亡协议（`/dh save`/`/dh stabilize`/团长
  `/dh confirmdeath`），不是战斗系统另外一套死亡判定。
- 战斗中没人回复时，团长可以像正式事件一样用 `/dh force` 跳过等待、直接
  用已交的行动结算这一回合。
- 目前是单体妖兽 MVP 版本，不支持一次面对多只妖兽，也没有独立的阵法子
  系统（详见 `world/combat_rules.md` 的"MVP 范围说明"）。

## 示例十：AI输出乱了，回退到某个时间点重来

人多的时候 AI 一次要处理好几份行动，偶尔会输出得比较混乱（人物弄混、
剧情前后矛盾之类）。这时候可以先看看最近几条 AI 叙事的记录点编号，再让
团长回退到某个点之前，相当于让那之后的一切都没发生过：

```
团长: /dh replay
机器人: 🕰️ AI叙事记录点（最近3条，共9条，最多保留50条）
        [T000007] 2026-07-05 21:10:03｜反应式叙事｜李昂
        　老匠人接过矿石，手指刚碰到就猛地缩回，脸色一下子变了……
        [T000008] 2026-07-05 21:12:40｜正式事件结算｜李昂、沈砚、王曦
        　长老盯着那块矿石看了许久，缓缓开口……
```

## 示例十二：托管代打，不让一个人拖住全团

之前提过用 `/dh force`/`/dh kick` 应对长期不回复的玩家，现在多了一个更
温和的选择：`/dh autopilot`，让 AI 按角色属性走最保守的路线替TA玩，人
还留在团里，不用被踢出去：

```
（玩家自己知道这几天没空上线）
李昂: /dh autopilot on
机器人: 🤖 李昂 已开启托管：正式事件会自动按角色属性提交最保守的行动，
        日常打坐保持小幅稳定的修为增益，不再推进剧情。托管期间发的消息不会被当作
        行动，需要发 /dh autopilot off 才能拿回控制权。

（几天后触发了一次正式事件，李昂人不在，但不会卡住其他人）
张衡: 我们冲进遗迹深处，看看到底藏着什么
机器人: ⚠️ 触发正式事件：遗迹与机缘！
        等待以下玩家提交行动：沈砚
        （团长可以用 /dh force 跳过等待，直接结算）
（李昂被自动记为："沉稳观察局势，尽量避免冲突，护住自身安全，绝不主动招惹是非"）

（李昂某天回来想重新自己玩）
李昂: 我去看看师傅这几天怎么样了
机器人: 🤖 李昂 当前处于托管状态，这句话不会被当作行动。发 /dh autopilot off 关闭托管后才能手动行动。

李昂: /dh autopilot off
机器人: ✅ 李昂 已关闭托管，恢复由真人控制。

李昂: 我去看看师傅这几天怎么样了
机器人: 🎭 ……
```

如果是团长发现某个队友一直不回复、又不方便直接踢人，也可以帮TA开：

```
团长: /dh autopilot 李昂 on
机器人: 🤖 李昂 已开启托管：……
```

**注意**：
- 托管角色的"保守行动"由代码按角色`心性`属性直接生成（心性高就沉稳观察，
  心性低就躲在后面），不调用 AI，跟六维属性一样"代码定数值，AI管叙事"。
- 每次团里推进一个 cycle（一次正式事件结算或一场战斗结束），托管角色会
  打坐吃一次固定的小额修为增益——时间线不会因为一个人挂托管就原地踏步，
  但也不会走冒险路线抢跑。
- 托管**不覆盖回合制战斗**（`/dh combat`）里的逐回合行动——托管角色如果
  卷进战斗，还是需要团长 `/dh force` 跳过等待。
- **必须显式发 `/dh autopilot off` 才能解除托管**——普通发言不会自动关闭，
  这是为了避免"随口一句无关的话"被误判成"回来了"而意外解除托管。

## 示例十三：编剧敕令，团长直接改剧情

正常情况下剧情都是"玩家说话 → AI 判断 → 反应式叙事/正式事件"这条路径
推进的。但有时候团长想直接让某件具体的事发生——比如遇到一个"见谁杀谁"
的麻烦NPC，不想让它继续搅局，可以用 `/dh decree` 直接下场：

```
团长: /dh decree 杀死那名见谁杀谁的魔修
机器人: 📜 那魔修狞笑着扬起爪来，天色骤然一暗，一道紫雷毫无征兆地劈落，
        正中他的天灵盖。焦黑的躯体轰然倒地，只余下一缕青烟，仿佛冥冥中
        自有裁决。
```

AI 不会生硬地写"魔修死了"，而是会安排一个合理的来源（天劫/隐藏阵法/
路过高人/势力暗中出手等），跟平时的因果规则保持一致。也可以用来平息
冲突、揭穿误会，或者补一段团长觉得该有但没自然发生的剧情：

```
团长: /dh decree 平息这场即将爆发的宗门冲突
机器人: 📜 就在双方剑拔弩张之际，两大长老忽然同时收到一封密信……
```

**注意**：
- `/dh decree` 只对**叙事**和**世界状态**生效，改不了角色的核心硬数值——
  跟平时的 STATE_DELTA 一样受保护字段机制约束，没法直接把某个玩家的
  生存状态改成"已死亡"，也没法直接改六维/修为。真要让某个玩家角色死，
  还是得走 HP 打到 0 → 濒死 → 死亡豁免 → 团长 `/dh confirmdeath` 这一整套
  流程，`decree` 顶多能把 HP 打下去，不能一步到位判定死亡。
- 每条敕令也会产生一个 `/dh replay` 记录点，写出来的东西不满意，可以
  `/dh rollback` 撤销重来。
- 仅 AstrBot 管理员可用。

## 示例十四：修炼成长——不是境界文字换一下就完事

境界不是喊一声就能涨的。角色有一条隐藏的"修为进度"（0~100，自己不会
直接看到具体档位判断依据，但 `/dh mycard` 能看到当前进度数字），靠日常
打坐修炼、战斗历练、服用自己持有的法宝丹药灵材、被人指点、被人灌顶
渡功、学到新功法这些真实途径慢慢攒：

```
李昂: 我找了个僻静地方打坐运功
机器人: 🎭 灵气缓缓在经脉中流转，李昂只觉得丹田处那点微光又亮了几分。

（进度攒到100才会真的触发"修行突破"这个正式事件）
李昂: 我感觉火候到了，尝试突破
机器人: ⚠️ 触发正式事件：修行突破！
（结算后）
机器人: 🎭 一声轻响，李昂只觉得体内那道瓶颈豁然而开——他的境界，
        从练气三层，跃升至练气四层。
```

**如果火候没到就硬冲**，机器人不会陪你演一场假突破，会照普通反应式
叙事处理（相当于"这次尝试还不到时候"）。境界卡在"练气九层→筑基"
"筑基巅峰→金丹"这两个大瓶颈的突破失败，风险比平时更高，可能伤气血、
落下病根，不是每次突破失败都无关痛痒。

**灌顶渡功**是所有途径里风险最高的一条——别人给你渡功力，能不能吃得
下取决于你自己的底子，失败了不但没捞到好处，还可能因为经脉承受不住
外来的功力而走火入魔：

```
沈砚: 我求老师父帮我渡一道功力，助我打通经脉
机器人: 🎭 老师父一掌抵上沈砚后心，滚烫的真气汹涌灌入——沈砚只觉得
        浑身经脉都在尖叫，眼前一黑，再站起来时，脸色苍白得像是大病一场。
（这次灌顶失败，沈砚可能因此染上一项持续病症）
```

灵根（天/地/玄/黄四个层级）不会靠日常修炼提升，只有"遗迹与机缘"这类
正式事件才有极小概率触发灵根蜕变——这是刻意的设计，机缘本来就该可遇
不可求，不是肝出来的。

### 修炼系统升级（LONG-A）

现在修炼系统有了更丰富的机制：

- **灵根纯度**：灵根不再只是"金/木/水/火/土"一个标签，还有纯度（0%~100%），
  纯度越高修炼越快、突破越容易。天灵根（纯度90%+）修炼速度是废灵根的五倍。
- **异变灵根**：有5%概率生出异变灵根（雷/冰/风/空间），修炼效率更高但突破
  时天劫风险也更大。
- **根基值**（0~200）：根基越稳固，突破越容易；突破失败会损伤根基。
- **瓶颈等级**（0~5）：连续突破失败会积累瓶颈，瓶颈越高修炼越慢、突破越难；
  突破成功可以打破瓶颈。
- **修炼倍率**：由灵根效率 × 功法速度 × (1 - 瓶颈衰减)综合计算。
- **技能能力**：剑意、炼丹、炼器、阵法、符箓五类技能独立于境界升级，
  低境界也可以有高技能。
- **宗门**：加入宗门可获得贡献点、学习宗门功法、职位晋升（目前为接口预留）。

新增 `/dh cultivate` 指令，可以主动打坐修炼获得修为进度：

```
李昂: /dh cultivate
机器人: 🌙 修炼完成
        修为进度：0 → 3/100
        境界：练气一层
        结果：小成（成功）
```

`/dh mycard` 现在会显示更多信息：灵根纯度、根基值、瓶颈等级、技能等级。

修为攒到100后，除了自然语言描述"我要突破"，也可以直接发指令：

```
李昂: /dh breakthrough
机器人: ⚠️ 触发正式事件：修行突破！
（结算后）
机器人: 🎭 一声轻响，李昂只觉得体内那道瓶颈豁然而开——他的境界，
        从练气三层，跃升至练气四层。
```

学习新功法、修炼技能、经营宗门也都有专门指令：

```
李昂: /dh technique
机器人: 📖 已学功法
        （尚未学习任何功法）
        💡 推荐可学：「流云诀」（黄级·水）
        用法：/dh technique <功法名> 学习

李昂: /dh technique 流云诀
机器人: 📖 学会了「流云诀」（黄级·水）！

李昂: /dh ability 剑意
机器人: 🎴 修炼「剑意」
        结果：成功（掷骰14）
        经验：+3（3/10）

李昂: /dh sect
机器人: ℹ️ 你还未加入任何宗门。先用 /dh join_faction <势力代号> 加入一个
        「宗门」类型的势力（用 /dh faction 查看势力代号和类型）。

李昂: /dh join_faction CULT-01
机器人: ✅ 你已加入「归墟宗」(CULT-01，宗门)。

李昂: /dh sect contribute
机器人: ⛩️ 为「归墟宗」贡献 +2 点（累计 2）

李昂: /dh sect worship 传功长老
机器人: 🤝 你正式拜「传功长老」（传功长老）为师！
```

**注意**：技能/功法/突破/宗门的数值（掷骰、经验、是否升级、能否学会）
全部由代码判定，跟战斗系统一样"代码管数字、AI 管叙事"，不受聊天内容
摆布。传承领取有具体数值效果（秘术传承+3攻/器物传承+3防常驻生效，
血脉传承+10气血上限/道心传承+5灵力上限/功法传承+5修为进度领取时立刻
到账）。`recruit`（收徒）也没有"对方确认"这类互动流程——是核心弟子
以上单方面执行的管理动作，跟 `/dh kick` 性质类似，社交层面的同意靠
团桌讨论，不在代码层面拦。

宗门还有一套简单的师徒任务系统：

```
张宗主: /dh sect assign 小徒儿 去后山采十株灵草
机器人: 📋 你给「小徒儿」布置了一项任务：去后山采十株灵草
        （对方可用 /dh sect complete 完成任务）

小徒儿: /dh sect complete
机器人: ✅ 你完成了「张宗主」布置的任务：去后山采十株灵草
        贡献点 +5（累计 15）
        「张宗主」因指点有方获得贡献点 +3
```

任务内容是纯文本记录，实际"有没有真的去后山采到灵草"由团里聊天描述、
AI 叙事来体现，`complete` 本身不校验剧情合理性——这是团长/玩家之间的
社交信任机制，跟 `decree`/`kick` 这类"由够格的人直接执行"的指令是
同一套设计哲学。

## 示例十五：这个世界有名有姓——势力与人物

东荒不是只有"中部""东部"这种方位标签，五大区域都有正式名字：**中部
（岱央）、东部（启阳）、南部（沃澜）、北地（玄朔）、西部（裂川）**。
每个区域下面还分了若干具体的子区域，你的角色开局就会被分到一个具体
地方，而不是笼统的"中部人"：

```
李昂: /dh mycard
机器人: 【李昂 的角色卡】
        ……
        所在地：中部·祖脉余山
```

这些地方背后有具体的宗门/王朝在实际管辖，你的角色跟这些势力互动时，
机器人会自动知道这里归谁管、掌权者是谁，不是 AI 现场瞎编：

```
李昂: 我去打听一下这附近是哪个宗门的地盘
机器人: 🎭 路人压低声音："这一带都是归墟宗的祖脉余山，宗主归尘真人
        已经闭关三十年了，宗里的事现在都是几位长老在张罗……"
```

游戏里提到的势力（比如"归墟宗""岱央李氏"）和具体人物名字，只要你在
对话里提起，机器人都会自动带出对应的背景设定——不需要你去查什么资料，
正常聊天提到名字就行。

## 示例十六：因果网络——欠下的债迟早要还

开局的因果事件只是第一笔"绑定的因果"，之后每次遗迹机缘/CHAOS异常/
因果回响这几类正式事件，都可能悄悄埋下一笔还没兑现的"因果债"。这笔债
不会一直挂着不管——将来某次正式事件触发前，机器人有概率把很久以前的
某件旧事翻出来，让新事件的走向明显呼应那件事：

```
李昂: /dh causal
机器人: 【李昂 的因果网络】
        ━━━━━━━━━━━━━━
        已经兑现/绑定的因果：
        · 开局因果同源（天降血雨）
        ━━━━━━━━━━━━━━
        还欠着、尚未兑现的因果债：
        · 遗迹与机缘（古钟自鸣） —— 迟早会翻旧账
```

不需要你自己记住这些细节，机器人会替你记着，该翻账的时候自然会在剧情
里体现出来。

## 示例十七：不知道该发哪个指令，直接问机器人

指令越来越多，记不住也没关系，发 `/dh ask` 加一句你想干的事，机器人会
帮你从所有指令里挑一个最匹配的推荐给你（只推荐，不会替你执行）：

```
新玩家: /dh ask 我想看看自己现在是什么状态
机器人: 💡 你可能想用：/dh mycard —— 查看自己的完整角色卡：属性/天赋/HP/持续病症/NPC关系

玩家: /dh ask 我想知道团里最近发生了什么
机器人: 💡 你可能想用：/dh history —— 回看本团团史记录，发生过哪些正式事件

（问了一个完全不沾边的事）
玩家: /dh ask 帮我点一份外卖
机器人: 🤔 没找到匹配的指令，这次的需求已经记下来了，建议联系管理员看看是否需要新增指令。
        想看完整指令列表发 /dh help。
```

**注意**：
- `/dh ask` 只负责"推荐"，不会替你执行那条指令——推荐了之后还要自己手动发一遍。
- 没匹配到任何指令时，机器人会把这次的需求写进日志（`logger.warning`），
  方便管理员事后查看是不是该补一个新指令。
- 想看完整列表（而不是让AI猜）随时可以直接发 `/dh help`。

## 常见问题

- **Q: 为什么我说的话机器人没反应？**
  A: 发 `/dh why`，机器人会把最近几条消息它内部是怎么判断的原样列出来
  （比如"AI判定为场外聊天，不回应"或者"团不在进行中，忽略"），一眼就能
  看出卡在哪一步。想做全面体检就发 `/dh doctor`——它会逐项检查 LLM 连通性、
  世界观文件、开团状态，并直接告诉你下一步该做什么。
- **Q: 能不能自己选角色的区域/属性？**
  A: 不能，现在是完全随机，这是刻意的设计——包括开局位置都不保证分散，
  大家可能凑一块也可能各自天涯。想要更有代入感的随机性，而不是"抽卡"。
- **Q: 隐藏主线是什么？我怎么知道自己有没有？**
  A: 每个角色都有一条，但机器人不会说、`/dh status` 也不会显示，只能靠你
  在游戏过程中自己留意、自己摸索。这是刻意的悬念设计。
- **Q: 群里有人说了悄悄话，为什么别人看不到？**
  A: 这个世界观区分 PUBLIC（公开）和 PRIVATE（私有）信息。目前这一版
  PRIVATE 内容只会存进你自己的角色档案，不会在群里显示——不是 bug，是
  刻意的设计（还没有做真正的私聊推送）。
- **Q: 为什么死亡了不能马上重新建卡？**
  A: 死亡需要团长/管理员先确认成立，这是刻意设计的"人类兜底"机制，防止
  AI 误判导致角色白白死掉。确认之后就可以 `/dh join` 重新报名了。
- **Q: 新角色能不能继承老角色的东西？**
  A: 不能，完全从零随机生成，这是这个硬核世界观刻意的设定。
- **Q: `/dh end` 和 `/dh stop` 有什么区别？**
  A: `/dh stop` 是暂停——所有存档原封不动，随时 `/dh start` 继续，相当于
  "存档关机"。`/dh end` 是彻底结束——会**永久清空**本群所有存档（角色档案、
  世界状态、事件历史），需要连发两次才生效，防止手滑。想清楚再发。
- **Q: 我能不能直接跟机器人说"给我三万灵石""把我修为提到筑基期"？**
  A: 不能，说了也没用。这类直接向 AI 要资源/改数值的话，会被判定成
  "跟游戏世界无关的场外喊话"，不会真的生效——所有数值变化只能通过真实
  的游戏行动（打坐修炼、正式事件、服用自己持有的物品等）产生，AI 不会
  因为你嘴上说了就照办，管理权限也只认 AstrBot 平台本身的身份，聊天里
  自称"管理员"没有任何效果。
- **Q: 这个世界感觉挺大的，是不是每次都会现编？**
  A: 大部分是提前写好的固定设定，不是每次现编——五大区域（岱央/启阳/
  沃澜/裂川/玄朔）、下面的具体子区域和地点、17个具体势力、几百个具名
  NPC，都是提前准备好的数据库，AI 只是从里面挑出跟你相关的部分讲给你听，
  同一个地方、同一个势力，不同的团玩到，背景设定是一致的。

## 世界事件系统

东荒世界不只是背景板——你做的事真的会影响正在发生的事件。

### 活跃事件

开团时，世界会自动产生 2~3 条初始事件（灵脉异动、势力冲突等），
这些事件会随着玩家的行动和团长的推进而发展。查看当前有哪些事件正在进行：

```
任意玩家: /dh status
机器人: 🌄 东荒跑团状态：active（Cycle-000001）
        ……
        ━━━━━━━━━━━━━━
        【当前活跃事件】
          灵气东移加速（灵脉资源·扩散，东部·启阳，高，进度 32%）
          西部封印松动（势力冲突·进行中，西部·裂川，紧急，进度 55%）
```

- 每条事件显示：标题、类别·阶段、区域·地点、优先级、进度百分比。
- 非管理员只能看到公开事件和同区域的事件；管理员能看到全部。
- 进度 100% 的事件自动结束并写入团史。

### 玩家行动推动世界

你在游戏里的行为会影响事件的发展——探索会推动遗迹类事件，战斗会推动冲突类事件，
修炼会推动灵脉类事件。这是静默发生的，你不会收到"你推动了某事件"的提示，
但你可以从新闻、NPC 反应和后续剧情中感受到世界在变化。

### 团长推进事件

```
团长: /dh advance
机器人: ⚡ 世界事件推进结果
        ━━━━━━━━━━━━━━
        【进度推进】2 条事件
          · 灵气东移加速：15.0% → 28.3%
          · 西部封印松动：55.0% → 63.7%
        【阶段变化】1 条事件
          · 灵气东移加速：萌芽 → 扩散
```

### 查看世界事件归档记录

```
团长: /dh eventlog
机器人: 📋 世界事件日志（最近3条，共3条）
        ━━━━━━━━━━━━━━
        [EP0001] Cycle-000001 灵脉资源｜灵气东移加速（PUBLIC）
        [EP0002] Cycle-000001 势力冲突｜西部封印松动（REGIONAL）
        [EP0003] Cycle-000001 遗迹与机缘｜中部古战场封印波动（PUBLIC）
```

- 仅管理员可用，默认显示最近 10 条，`/dh eventlog 20` 可看更多（最多 30 条）。
- 只显示 EventPool 归档的事件记录，跟 `/dh history` 的正式团史是分开的。

### 调试命令

```
团长: /dh eventtest explore 东部 启阳
机器人: ⚡ EventPool 玩家行为模拟结果
        受影响事件：灵气东移加速（灵脉资源）
        进度：0.1500 → 0.2347
        阶段未变
```

- 仅管理员可用，用于测试事件系统是否正常响应。
- action 可选：explore / battle / cultivate / trade / investigate / join_faction / leave_faction / travel。

## 使用限制

- 所有功能都只能在**群聊**里使用，私聊没有效果。
- 每条会触发 AI 判断的消息都要问一次模型，如果用的是本地部署的模型，
  响应速度取决于你的硬件和模型大小，建议先小规模测试确认能接受；开团时
  生成世界观 + 给每个人生成角色 + 依次播报，是好几次额外的 AI 调用，
  人多的话开团这一下会明显比平时的单条回复慢，是正常现象。
- `@QQ号` 这种播报目前是纯文字前缀，不一定会在你的 QQ 客户端里变成
  可点击的"@提醒"效果，取决于具体的适配器/客户端支持情况。
- AI 返回的状态格式有问题时，代码会直接丢弃这次变化（只保留叙事文字），
  不会尝试自动修复；事件历史本身"只增不改"。想整体撤销一段时间的内容，
  用 `/dh replay` 找到记录点、`/dh rollback` 回退，见示例十。
- "最终世界事件"目前只是埋下伏笔、存进世界状态里供 AI 后续引用，还没有
  一套专门检测"什么时候该正式触发"的机制，需要团长自己根据剧情进展
  掌握节奏、临场推动。
